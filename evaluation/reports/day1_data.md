## 6. 미래 정보 차단 점검 (leak-guard)

| 회차 | 대상 | 결과 | 조치 |
|---|---|---|---|
| 1차 | 수집 코드 | 확정 유출 없음. DART 날짜 비교 경계 버그(의심) | `dart_as_of`가 날짜만 남겨 비교하도록 수정, 테스트 추가 |
| 2차 | 학습용 표, 정답, 뉴스 수집 | **확정 유출 1건**: RSS 발행 시각이 미국 서부 자정으로 잘림. 의심 2건: FRED 금리·VIX 공개 지연, GDELT 15:15 정각 배치 | RSS는 그날(미국 서부) 끝을 발행 시각으로 처리. 금리·VIX를 yfinance로 교체. 15:15 정각 배치는 그날에서 제외 |
| 3차 | 수정 확인 | 코드 지적 5건 모두 해결. 옛 코드로 돌던 수집이 정리본을 오염 | 수집이 끝난 뒤 새 코드로 다시 정리 |
| 4차 | 최종 확인 | **확정 유출 없음** | 7절 |

**시점 규칙을 지키는 장치**
- 국내 지표는 모두 계산한 뒤 표 전체를 하루 늦춘다.
- 해외 값은 현지 날짜 < t인 값만 붙인다(같은 날짜 금지).
- 표를 만들 때마다 "사용한 원천 날짜 < t"를 자동으로 확인한다.
- 정답 관련 열 이름이 들어오면 막는다.
- 테스트 45개. 그중 "t일 이후 데이터를 3배로 바꿔도 t일 행이 변하지 않는가"를 확인하는 테스트가 있다.

## 7. 최종 leak-guard 결과

**판정: 확정 유출 없음** (테스트 45개 통과)

**뉴스 정리본** (35,105행 = GDELT 33,346 + RSS 1,759)
- 자기 신호일 구간을 벗어난 기사: 0건. 13개 신호일 모두 가장 늦은 기사는 t일 15:00이다.
- 신호일을 다시 계산했을 때 어긋난 기사: 0건.
- RSS 발행 시각 처리가 규칙과 다른 기사: 0건.
- 옛 방식으로 처리된 RSS 기사: 0건.
- 중복 URL: 0건.

**15:15 경계:** 신호일 배정, 구간 확인, GDELT 수집이 모두 같은 경계를 쓴다. 15:15 정각 기사는 다음 신호일로 간다.

**학습용 표·정답:** 최신 코드와 원본 기준으로 만들어졌다. 금지 열이 없다. `ret_5d` 같은 열은 이름만 보면 미래 값처럼 보여 따로 확인했다. 과거 5일 수익률과 상관이 1.0, 미래 5일 수익률과는 0.004로 과거 값이 맞다.

**남은 권고 (유출 아님)**
- 처음 수집할 때 옛 코드를 써서, 각 신호일 구간의 시작 배치(t-1일 15:15)가 빠져 있다. 하루 15분어치라 영향은 작다. 2~4월 전체를 받을 때는 새 코드를 쓰므로 생기지 않는다.
- 옛 `<날짜>.parquet` 원본에는 옛 방식 RSS 행이 남아 있다. 원본은 수정하지 않으므로, 읽는 쪽(`collect_news.main`)에서 GDELT 행만 쓴다.

## 9. 2일차로 넘기는 것

1. **기사 선별 기준:** 하루 약 2,700건에서 30건을 고르는 기준을 정한다. 예를 들어 삼성 직접 언급, 한국어, 거시 키워드의 비중을 정한다.
2. **정답 분포 변화:** 학습 구간에는 보합이 많고, 검증 구간에는 상승이 많다. 이 차이가 모델과 성공 기준에 주는 영향을 3일차 보고서에서 함께 해석한다.
3. **워크포워드 간격:** 학습 끝과 검증 시작 사이에 5거래일 간격을 둔다(train.py, leak-guard 권고).
4. **2~4월 전체 뉴스:** 본 채점 직전에 data-probe로 출처를 다시 점검한 뒤, 약 94GB를 받으면서 바로 거른다.
